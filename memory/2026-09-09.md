# 2026-09-09 Memory

## Cron 停摆 7 天事故

**问题：** 从 9 月 2 日起 4 个新闻情报收集 cron 任务全部停止运行。
**根因：** `~/.openclaw/cron/jobs.json` 的 `message` 字段中混入了 28 个未转义的原始换行符，导致 JSON 无法解析，调度器读不了配置。
**修复：** 用 Python 脚本转义所有非法换行符，恢复有效 JSON，重启 Gateway。

## Cron Prompt 全面翻新

修复后一次性解决了多个冷启动隐患：
1. **文件访问死锁** → 分层规则：dedup 阶段不读主文件，generate-data.mjs 失败时可以读取定位坏记录
2. **Git pull 冲突** → 加 `git stash || true` 和 `cd /root/.openclaw/workspace`
3. **`{date}` 歧义** → 明确为 `{TODAY} = 当前运行日期 YYYY-MM-DD`
4. **旧候选文件残留** → 写入前 `rm -f tmp/news-candidates-*.json`
5. **timeout 掐死** → 3600s → 4500s
6. **脚本零容错** → 开头检查 `test -f` 两个脚本是否存在
7. **Evening 错误状态** → 重置 consecutiveErrors=0
8. **翻译规则** → 保留英文：公司名/产品名/代码/技术缩写；其余全译中文
9. **ID 生成** → `{date}-{english-slug}`，标题关键词转英文，小写连字符，最多 5 词
10. **review_date** → 默认 date+7 天，长期事件（horizon≥1q）则 +30 天
11. **Yahoo 股票超时** → 明确说明这是正常 fallback 行为，不要 panic

## dedup-and-merge.mjs 容错增强

原脚本在字段缺失时 `throw new Error` 直接崩溃整个流程。

已推送修改到 main。

## 教训
- jobs.json 的 message 字段必须用 `\n` 转义，不能用原始换行符。任何编辑此文件的操作都必须验证 JSON 有效性。
- 搜索关键词需要覆盖产业链上下游（客户动态、设备、材料），不能只聚焦原厂。
- 冷启动时 AI 不会主动扩展关键词，必须显式写入 prompt。
